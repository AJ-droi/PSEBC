# Deployment (zero budget, UK/EU hosting)

| Piece | Free option | Region |
| --- | --- | --- |
| Database | **Neon** free plan | AWS London (`eu-west-2`) |
| API (Express) | **Render** free web service (`render.yaml`) — or Railway / Fly / any Docker host (`apps/api/Dockerfile`) | Frankfurt |
| Web app (Next.js PWA) | **Vercel** Hobby (non-commercial charity use) — or Netlify / Render | choose `lhr1` / `fra1` function region |
| Scheduled checks | GitHub Actions (`.github/workflows/scheduled-jobs.yml`) | — |

## 1. Neon

1. Create a project at neon.tech → region **London (AWS eu-west-2)** → database `psebc`.
2. Copy the **pooled** connection string (host contains `-pooler`), with `?sslmode=require`.
3. Run the migrations and (only for a demo) the seed from your machine:

   ```bash
   DATABASE_URL="postgresql://…-pooler…/psebc?sslmode=require" \
   JWT_SECRET=x DATA_ENCRYPTION_KEY=$(openssl rand -base64 32) \
   npm run db:migrate
   ```
   Migrations (generated by Drizzle into `apps/api/drizzle/`) also run automatically every time the API starts.

4. Create a second Neon *branch* for testing (`TEST_DATABASE_URL`) — the journey test wipes its database.

## 2. API on Render

1. New → Blueprint → point at this repository (uses `render.yaml`).
2. Fill the secret values:
   * `DATABASE_URL` — the Neon pooled string
   * `DATA_ENCRYPTION_KEY` — `openssl rand -base64 32` (**keep a copy in the church password manager — losing it makes health notes unreadable**)
   * `WEB_ORIGIN` — the web app URL, e.g. `https://lifts.princesstreet.org`
3. Check `https://<api>/api/health` returns `{"ok":true}`.

Render's free plan sleeps after 15 minutes idle. The GitHub Actions cron (step 4) wakes it every 10 minutes,
so lifts stay responsive around services. For a guaranteed always-on API, use any small paid plan later.

## 3. Web app on Vercel (or Render)

`render.yaml` also defines the web app as a second Render service (`psebc-web`), so a Render Blueprint
deploys both. See [release-epics-1-3.md](release-epics-1-3.md). For Vercel instead:

1. Import the repository → **Root directory** `apps/web` → framework Next.js.
2. Environment variable `API_URL=https://<your-api-host>` (no trailing slash).
3. Optional: add the church's domain. The app is installable from the browser ("Add to Home Screen").

## 4. Scheduled checks

In GitHub → Settings → Secrets → Actions add `API_BASE_URL` (the API URL) and `JOBS_SECRET`
(copy it from the Render environment). The workflow then calls `POST /api/jobs/run` every 10 minutes:
unmatched alerts (24 h / 2 h), 72-hour log timeout, DBS/insurance reminders and expiry, day-before
reminders, data retention and the notification outbox.

## 5. Text messages and email

**Every notification and alert is also emailed to everyone it concerns** — the logins it is sent to,
invited/booked drivers, the member (their login, or the email on their profile if they have no login),
their representative when an email is on file, and the office staff given a "please call" task. Each
person gets one email per message, with a button that opens the right page in the app.

By default messages are written to the app and logged (`NOTIFY_*_DRIVER=console`). To send real email:

* **Resend (recommended)** — in Resend, verify the church's sending domain (add the DNS records it shows)
  and create an API key with sending access. Then set `NOTIFY_EMAIL_DRIVER=resend`, `RESEND_API_KEY` and
  `EMAIL_FROM` (e.g. `PSEBC Lifts <lifts@your-church.org>`, on the verified domain), and optionally
  `EMAIL_REPLY_TO` so replies reach the church office. Emails go over HTTPS, so blocked SMTP ports don't
  matter. Each email carries an idempotency key (`psebc-notification/<id>`), so a retry after a timeout never
  sends it twice. Rate limits and outages are retried (up to 5 times); a rejected email — bad address, wrong
  key, unverified domain — is not retried, and Resend's reason is kept in `notifications.last_error`.
  The API refuses to start without a key, or with the placeholder `@example.org` sender.
* **SMTP** — set `NOTIFY_EMAIL_DRIVER=smtp` and `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`,
  `SMTP_PASS`, `EMAIL_FROM` (and optionally `EMAIL_REPLY_TO`). Works with the church's Microsoft 365
  (`smtp.office365.com:587`, dependency in PRD §11), Google Workspace, or a provider such as Brevo, Resend
  or SendGrid. Use `SMTP_SECURE=true` for port 465. The API refuses to start if `smtp` is chosen without a host.
* **Webhook** — set the driver to `webhook` and `NOTIFY_WEBHOOK_URL` to a flow that accepts JSON
  `{ channel, to, subject, body, html }` — for example a **Power Automate** flow, GOV.UK Notify or Twilio.

Texts use `NOTIFY_SMS_DRIVER=webhook` the same way. Adapters live in `apps/api/src/services/senders.ts`
and the email layout in `apps/api/src/services/email-template.ts`. Failed sends are retried up to 5 times
(see `notifications.last_error`).

## 6. Message alerts with sound

* **While the app is open**, every signed-in screen plays a short chime (and vibrates phones) when a new
  message arrives. Nothing to set up. People can switch the sound off under **Messages**.
* **When the app is closed or the phone is locked**, the app uses Web Push. Generate the keys once:

  ```bash
  npx web-push generate-vapid-keys
  ```

  Put them in the API environment as `VAPID_PUBLIC_KEY` and `VAPID_PRIVATE_KEY` (plus `VAPID_SUBJECT`,
  e.g. `mailto:office@princesstreet.org`). Keep the private key secret; changing the keys means everyone
  has to turn alerts on again. Each person then taps **Turn on alerts** once on each device.
* **iPhone/iPad:** alerts only work after the app is added to the Home Screen (iOS 16.4 or later).
* **Privacy:** an alert shows on the lock screen, so it carries only a generic title such as
  "New lift request" — never names, addresses, times or health information.

## 7. First real users

1. Sign in as the seeded admin **only on a demo database**. On the live database, create the first admin
   directly:

   ```sql
   -- password hash from: node -e "console.log(require('bcryptjs').hashSync('a long password', 12))"
   INSERT INTO users (email, full_name, role, password_hash) VALUES ('office@…', 'Church Admin', 'admin', '<hash>');
   ```
2. Admin → Logins: add Mathias (safeguarding) and coordinators. Both admin and safeguarding set up an
   authenticator app on first sign-in.
3. Settings such as the church office phone number live in the `settings` table.

## 8. Backups

Neon keeps point-in-time history (free plan: 24 h). Add a weekly `pg_dump` (e.g. a GitHub Action writing to
the church's OneDrive) if longer retention is required by the safeguarding policy (trip logs: 6 years).
